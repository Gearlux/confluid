# Confluid bug report — 2026-08-13 hunt

Every bug below is **confirmed by running the reproduction shown** (outputs pasted verbatim,
loggair banner stripped). Each entry: the use case, the complete runnable example, the measured
actual output, and the expected behaviour with the mandate/doc it violates. Run any example with
`/Users/gert/taidal/.venv/bin/python script.py` from an empty directory.

**Glossary (read this first):**
- **`Target`** — confluid's recipe class. `Target(Engine, power=5)` is NOT an Engine; it is a note
  saying "build `Engine(power=5)` later". Every YAML `_target_:` mapping parses into one. It was
  named `Class`/`Instance` until the 2026-08-11 merge-and-rename that matched it to the `_target_`
  key. Production code almost never writes it by hand.
- **`PartialClass`** — the deferred variant of the same recipe: "build it even later, when I hand
  you the missing argument" (`flow(self.optimizer, params=model.parameters())`). This is the form
  production code actually writes (14 body slots in matrainer alone).
- **marker** — any such recipe object sitting in a config tree.
- **the load path** — what happens inside `load()` / `materialize()`: parse YAML, resolve, build.
- **the configure path** — `configure(obj, config=...)`: apply a document to objects that already
  exist.

Severity: **S1** = silent wrong answer on a mainstream spelling · **S2** = silent wrong answer on a
plausible spelling · **S3** = crash/untyped error on legal input · **S4** = contract divergence with
narrow blast radius.

# Part P — parse time (loader / resolver / merger / scopes)

## P1 · S1 — An include-file override of one kwarg silently DELETES the whole marker

**Use case:** the single most common composition in the workspace — a base file defines the model,
the experiment file includes it and overrides one knob.

```yaml
# base.yaml
model:
  _target_: collections.Counter
  red: 1
```
```yaml
# experiment.yaml
include: base.yaml
model:
  blue: 3          # "same model, one more kwarg" — the natural reading
```
```python
from pathlib import Path
from confluid import load

Path("base.yaml").write_text("model:\n  _target_: collections.Counter\n  red: 1\n")
Path("experiment.yaml").write_text("include: base.yaml\nmodel:\n  blue: 3\n")

result = load("experiment.yaml")
print(type(result["model"]), result["model"])
```
**Actual (measured):** `<class 'dict'> {'blue': 3}` — the `_target_` and `red: 1` are gone; no
model is constructed, no warning, no error. The dotted spelling of the *same* override
(`model.blue: 3`) tunes the marker correctly: `Counter({'blue': 3, 'red': 1})`.

**Expected:** the overlay mapping merges into the marker's kwargs (the documented "a mapping
addressed at a slot holding a marker TUNES it, never replaces it") → `Counter({'blue': 3, 'red': 1})`.
Two spellings of one override must agree ("a behaviour reachable from only one spelling is a BUG").
**Where:** `confluid/merger.py:41-48` (`deep_merge` — a Fluid base is not a dict, so the overlay
replaces it), reached from `loader._splice_includes`.

## P2 · S1 — FIXED 2026-08-15 (`tests/test_plain_format.py`, merge-key group) — Reserved keys delivered by a YAML merge key (`<<:`) are never converted

**Use case:** the standard YAML pattern for "many variants of one node" — anchor a base marker,
`<<:` it into each variant. This is exactly the plain-format promise ("ordinary YAML that
`yaml.safe_load` reads" — merge keys are core YAML 1.1).

```python
from confluid import load, flow

result = load("""
base: &b
  _target_: collections.Counter
derived:
  <<: *b
""", flow=False)
print("base   :", type(result["base"]).__name__)
print("derived:", type(result["derived"]).__name__, result["derived"])
```
**Actual (measured):**
```
base   : Target
derived: dict {'_target_': 'collections.Counter'}
```
`derived` is an inert dict carrying a literal `_target_` key that nothing downstream ever converts
(conversion is parse-time-only by mandate). Inconsistently, `{<<: *b, _partial_: true}` — one
literal reserved key present — DOES convert.

**Expected:** `derived` is a `Target` like `base` (flatten merge keys before the reserved-key node
test), or a located error. Never a silent inert dict.
**Where:** `confluid/loader.py:519-521` (node-key test reads literal scalar keys, pre-flatten).

## P7 · S1 — A dotted key beats a nested block regardless of document order

**Use case:** any document mixing the two spellings of the same leaf — including the include
pattern (`a.b: 1` written above an `include:` whose base file says `a: {b: 0}`).

```python
from confluid import load

r1 = load("a.b: 1\na:\n  b: 0\n", flow=False)   # nested written LAST → nested should win
r2 = load("a:\n  b: 0\na.b: 1\n", flow=False)   # dotted written LAST → dotted should win
print(r1, r2)
```
**Actual (measured):** `{'a': {'b': 1}} {'a': {'b': 1}}` — the dotted spelling wins in BOTH
orders; the two orderings do not disagree.

**Expected:** `{'a': {'b': 0}}` then `{'a': {'b': 1}}` — "There is ONE precedence rule: DOCUMENT
ORDER, last spec wins … a dotted key … competes on POSITION and nothing else."
**Where:** `confluid/merger.py:113-134` — the dotted pass runs after the plain pass and assigns
unconditionally.

# Part I — introspection / schema / validation

## I1 · S1 — Body slots assigned by tuple unpacking are invisible — a bare key silently does not land

**Use case:** an ordinary constructor unpacking a pair: `self.alpha, self.beta = compute_defaults()`.

```python
from confluid import Target, configurable, materialize

@configurable
class Normal:
    def __init__(self):
        self.alpha = 1
        self.beta = 2

@configurable
class Unpacked:
    def __init__(self):
        self.alpha, self.beta = 1, 2      # SAME two slots, tuple-assigned

for cls in (Normal, Unpacked):
    marker = Target(cls)
    obj = materialize({"obj": marker, "alpha": 99})["obj"]
    print(cls.__name__, "alpha after bare-key broadcast:", obj.alpha)
```
**Actual (measured):**
```
Normal alpha after bare-key broadcast: 99
Unpacked alpha after bare-key broadcast: 1     # the sweep key silently did nothing
```
Also invisible: `for self.idx in …:`, `with open(p) as self.stream:`, `self.head, *self.tail = …`.

**Expected:** both classes answer alike — `self.alpha, self.beta = …` declares the same body
slots as two plain assigns. This is the silent-config-drop class the report/B1 mandates exist to
kill. **Where:** `confluid/introspect.py:204-232` (`_self_attr` never unpacks `ast.Tuple`/
`ast.Starred` targets, `ast.For.target`, `ast.withitem.optional_vars`).

## I2 · S3 — A self-referential class dies with `RecursionError` at first construction under the DEFAULT policy

**Use case:** any tree/linked structure: `Node(child: Optional["Node"] = None)`.

```python
from typing import Optional
from confluid import configurable

@configurable
class Node:
    def __init__(self, child: Optional["Node"] = None):
        self.child = child

Node()          # first construction, default validation policy
```
**Actual (measured):** `RecursionError: maximum recursion depth exceeded` — the validation wrap
calls `to_pydantic(Node)`, which recurses `Node → Node → …`. The docstring's claim that the
lru_cache "returns the in-flight class on second visit" is false (lru_cache memoizes only after
return). Mutually-recursive pairs (`A→B→A`) die the same way.

**Expected:** a usable model via forward-ref/in-flight sentinel, or at minimum a located
`IntrospectionError` — never a stack overflow on an ordinary class shape.
**Where:** `confluid/pydantic_export.py:372-381`.

## I3 · S1 — A `@configurable` class with NO own `__init__` accepts EVERY bare key in the document

**Use case:** a marker/mixin class: `@configurable\nclass NoInit: pass`.

```python
from confluid import Target, configurable, materialize

@configurable
class NoInit:
    pass

@configurable
class EmptyInit:
    def __init__(self): pass

for cls in (NoInit, EmptyInit):
    obj = materialize({"obj": Target(cls), "totally_random": 42})["obj"]
    print(cls.__name__, "totally_random:", getattr(obj, "totally_random", "<absent>"))
```
**Actual (measured):**
```
NoInit totally_random: 42          # every bare key in the document lands on it
EmptyInit totally_random: <absent>
```
`slots(NoInit)` reports the phantom `*args/**kwargs` of `object.__init__`, and any `var_keyword`
slot makes the accept-list `None` = accept-everything. `to_pydantic` guards this exact case;
`slots()` does not — a reader disagreement of the kind record 12 exists to prevent.

**Expected:** a class declaring no constructor declares nothing; `NoInit` ≡ `EmptyInit`.
**Where:** `confluid/introspect.py:101-103` + `435-459`; `confluid/broadcast.py:386-396`.

## I4 · S1 — A QUOTED body-slot annotation loses its meaning: `"Partial[Optim]"` builds eagerly

**Use case:** a quoted annotation to avoid an import at module top (a very common Python habit).

```python
from confluid import PartialClass, configurable
from confluid.partial import Partial, partial_param_names

class Optim: ...

@configurable(validate=False)
class QuotedTrainer:
    def __init__(self):
        self.optimizer: "Partial[Optim]" = None      # quoted — the ONLY difference

@configurable(validate=False)
class PlainTrainer:
    def __init__(self):
        self.optimizer: Partial[Optim] = None

print("plain :", partial_param_names(PlainTrainer))
print("quoted:", partial_param_names(QuotedTrainer))
```
**Actual (measured):**
```
plain : {'optimizer'}
quoted: set()        # the deferral is LOST — the slot's marker gets eagerly built
```
Asymmetric: the same quoted spelling on a *constructor param* IS detected (get_type_hints resolves
it); only the body-slot path leaks the raw `str` as `Slot.annotation` instead of resolving or
degrading to `Any`.
