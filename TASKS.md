  - [ ] **Phase 5c — retire the TAG constructors** @v0.4.0 — deferred out of 0.3.0 by user decision (2026-08-11). **0.3.0 ships the tags AND `confluid-migrate`; 0.4.0 deletes them.** The reason is the codemod itself: `migrate.verify_equivalence` parses the ORIGINAL tagged text (`yaml.load(before, Loader=ConfluidLoader)`, migrate.py:546) to prove a conversion equivalent, so deleting the constructors in the same release that ships the tool would make it refuse every file it exists to convert — and v0.1.0/v0.2.0 are on PyPI, so an outside user with tagged configs needs exactly that path.   - [ ] **Phase 5e — the QUOTED-STRING spelling is a third grammar nobody deprecated** @v0.4.0 — surfaced by the 2026-08-12 example sweep. `"!class:Adam(lr=!ref:base_lr)"` is parsed by `resolver._parse_class_string` / `Resolver.resolve`, NOT by a tag constructor, so it (a) emits no `FutureWarning`, (b) is reported-not-converted by `confluid-migrate`, and (c) supports only `!class:` and `!ref:` — `"!lazy:X"` and `"!clone:x"` load as PLAIN STRINGS with no error, which is exactly the silent degradation the reserved-key format exists to end. It also binds DIFFERENTLY: inline values resolve eagerly against the context, where `_target_`'s `${ref:...}` stays a late-bound `Reference` (measured converting `examples/ml_pipeline.py`, where the deferred slot is flowed outside the document and the Reference then cannot resolve — so `verify_equivalence`, which compares in-document resolved trees, would call the two equivalent). Decide: warn + teach the codemod to rewrite it, or raise on the three markers it drops. `configurator.py:94` is on the same path.

- [ ] **`AppliedKey.loc` — a clickable `file:line` for the contest** @feature @low — `explain(key)` (2026-08-12) reports document ORDER, which is what explains a surprise; it cannot report WHERE, because only Fluid markers carry a location (`loader._stamp_loc`). A bare `lr: 0.9` has none: PyYAML's default mapping constructor discards per-key marks. Adding one means a location side-table built in `map_constructor` and carried through `_splice_includes` and `deep_merge`, both of which REORDER keys by design — so it lands in the merge layer with the most adjudication history. Worth doing only if reading the index is not enough in practice.
