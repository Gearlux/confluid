- [ ] **Warn on a duplicate registration NAME** @bug @low — `ConfluidRegistry.register_class` does `self._classes[cls_name] = cls` with no check, so registering two different classes under the same name silently overwrites the first. Found while registering the Keras loss/metric set for an image classifier: Keras publishes thirteen names under BOTH `keras.losses` and `keras.metrics` (`BinaryCrossentropy`, `Hinge`, `KLDivergence`, …), and registering both spellings would have replaced each loss with its metric namesake — invisibly, since both are `task="classification"` configurables. A `logger.warning` when the name is already bound to a DIFFERENT object (re-registering the same object is legitimate — navigaitor's snapshot restore does it) would turn a silent picker corruption into a one-line CI signal.
